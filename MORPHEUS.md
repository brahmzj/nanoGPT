# Morpheus

*A tiny mind that grows up from the ABCs and 1 2 3s.*

Most language models are poured full of the internet first and taught manners later.
Morpheus goes to school instead. It starts knowing nothing but 96 symbols, learns
`a b c`, then counting, then sums, words, little facts about the world, and finally
how to hold a conversation. It moves on only when it passes each stage's exam.
The whole curriculum is generated by code, so there is no dataset to download. When
school is over, the brain is squeezed to **1.58 bits per weight** (every weight is -1, 0 or +1).
The whole mind is a **153 KB** file that scores as well as the 2.6 MB original, and it runs
with **numpy alone**.

After school, Morpheus becomes a **personal assistant**. It keeps notes, keeps your list,
sets reminders and alarms, checks its own math, and **keeps learning on your phone** from
files, from what you teach it, and from the internet only when you allow it. It learns only
while charging, and it rolls back any session that makes it forget.

**On Android:** see [android/README.md](android/README.md), a one-command install in Termux.

```
you> what comes after k?
morpheus> after k comes l.
you> how do you spell elephant?
morpheus> elephant is spelled e l e p h a n t.
you> what is 7 x 8?
morpheus> 7 x 8 = 56.
you> remember that my locker code is 4071
morpheus> ok, i will remember that your locker code is 4071.
you> what is my locker code?
morpheus> your locker code is 4071.
you> what is the capital of france?
morpheus> i have not learned that yet. will you teach me?
```

## Quick start

```sh
pip install torch numpy                 # numpy alone is enough to *run* a trained Morpheus
python -m morpheus train                # raise Morpheus (CPU is fine, see results below)
python -m morpheus chat                 # talk to it
python -m morpheus exam                 # report card for every stage
python -m morpheus stats                # size / compute budget
python -m morpheus squeeze --scheme ternary        # compress to 1.58 bits and keep learning
python -m unittest tests.test_morpheus tests.test_device   # 48 tests, a few seconds
```

Run the commands from the repository root. A trained brain ships in
[`brains/morpheus-nano.morph`](brains/morpheus-nano.morph), so `chat` works straight away
with only numpy installed. Training writes `out-morpheus/morpheus.pt` (full checkpoint,
resumable with `--resume`) and `out-morpheus/morpheus.morph` (the compressed brain).

## How Morpheus learns

| # | stage       | what it studies                                                          | sample exam question               |
|---|-------------|--------------------------------------------------------------------------|------------------------------------|
| 1 | `letters`   | the alphabet, runs, after/before, big and little letters                 | `after k comes` → `l`              |
| 2 | `numbers`   | counting (by 1, 2, 5, 10), number words, counting stars, bigger/smaller  | `* * * * is` → `4`                 |
| 3 | `math`      | `+ - x /` facts, doubles and halves                                      | `7 x 8 =` → `56`                   |
| 4 | `words`     | spelling, a is for apple, animal sounds and legs, colors, opposites, plurals | `one mouse, two` → `mice`      |
| 5 | `world`     | days, months, seasons, world facts, story problems                        | `sam has 3 cups. sam gets 2 more. now sam has` → `5 cups.` |
| 6 | `talk`      | conversation (`user:` / `morpheus:`) about everything above               | `user: what color is the sky?` → `the sky is blue.` |
| + | `library`   | *optional:* your own `.txt` files (`--library my_books/`)                 | no exam; it just reads             |
| z | *dream*     | reviews every stage while the learning rate fades to zero                 | final report card                  |

Four ideas do the work:

1. **Procedural lessons, no dataset.** [`morpheus/curriculum.py`](morpheus/curriculum.py) *is* the data:
   a few hundred lines of generators produce an unlimited stream of lessons.
   Every fact is written once as `(prompt, answer, rest)`, so the lesson
   (`prompt + answer + rest`) and the exam question (`prompt → answer`) can never
   disagree. A test checks that no exam prompt is ever continued in two different
   ways anywhere in the curriculum. If it were, even a perfect student would fail.
2. **Mastery gating.** Every 100 steps Morpheus sits a *fresh* 200-question exam on the
   current stage and graduates at 95%. Easy stages end in seconds instead of burning
   a fixed step budget. This is the biggest energy saver in training.
3. **Spaced repetition.** 30% of every batch reviews earlier stages (`--replay`), so
   learning to spell does not erase counting.
4. **Dreaming.** After school, Morpheus reviews everything while the learning rate
   anneals to zero. This is when memories consolidate, as in sleep. Morpheus is the
   god of dreams, after all.

Exams are graded in a single forward pass with teacher forcing. For greedy
decoding, "the model says the answer" is exactly equivalent to "the argmax at every
answer position is the right character". That makes an exam about as cheap as a third of a
training step (a test verifies the equivalence against real generation). Answers that end a
fact include the newline, so Morpheus is also graded on knowing when to *stop* talking.

## Why it is light

**The alphabet.** 96 fixed symbols (newline + printable ASCII). Every token is 1 byte
(nanoGPT stores 2), the embedding table is tiny, and it is the same alphabet from
stage 1 to the end, so what is learned about letters carries forward.

**The brain** ([`morpheus/model.py`](morpheus/model.py)): every change from GPT-2 either removes parameters or removes work.

| choice                         | saves                                                                |
|--------------------------------|----------------------------------------------------------------------|
| RMSNorm with no weights        | parameters and the mean-subtraction of LayerNorm                     |
| rotary positions (RoPE)        | the whole position-embedding table                                   |
| grouped-query attention        | half the key/value weights and half the KV cache (4 query heads, 2 kv heads) |
| ReLU² MLP                      | cheap activation, and most of its outputs are exact zeros            |
| tied embeddings, no biases     | a second vocab matrix and every bias vector                          |
| `n_loop` weight sharing        | the `loop` size runs 2 blocks twice: depth 4, half the storage       |
| KV cache in generation         | each new character costs 1 position of work, not a full re-read (nanoGPT recomputes everything) |

| size    | parameters | width x depth | compute per character |
|---------|-----------:|---------------|-----------------------|
| `pico`  | 0.14 M     | 64 x 3        | 0.33 MFLOP            |
| `nano`  | 0.73 M     | 128 x 4       | 1.6 MFLOP (default)   |
| `loop`  | 0.37 M     | 128 x (2x2)   | 1.6 MFLOP             |
| `micro` | 2.38 M     | 192 x 6       | 5.1 MFLOP             |

GPT-2 small uses about 250 MFLOP per token, roughly 150x more than `nano`.

**Compression** ([`morpheus/compress.py`](morpheus/compress.py)): a `.morph` file is a JSON header (config, alphabet,
tensor table) plus an LZMA-packed payload. Weights are stored as float, int8, int4, int3, ternary
or binary. See [Compression to the extreme](#compression-to-the-extreme-squeeze).

**The numpy runtime** ([`morpheus/runtime.py`](morpheus/runtime.py)): about 120 lines that mirror the torch model exactly
(tests compare the two to 1e-4) and keep a KV cache. Training needs PyTorch; thinking
does not. Copy `morpheus/` and a `.morph` file to a Raspberry Pi and chat.

## Results

Measured on a 4-core cloud CPU with no GPU.

**Raising Morpheus** (`python -m morpheus train`, size `nano`, 733K parameters). Every stage
graduated on mastery:

| stage   | steps to graduate |
|---------|------------------:|
| letters | 300    |
| numbers | 1,100  |
| math    | 400    |
| words   | 1,400 (spelling made-up words too) |
| world   | 2,700  |
| talk    | 3,500  |
| dream   | 1,500  |

That's 10,900 steps. An earlier run of 11,500 steps with the CPU to itself took **21.5 minutes**,
an estimated **~9 Wh** at 25 W, about what a laptop uses in 20 minutes.

**Compression to the extreme.** The same brain in every format, graded on the same fresh exam
(300 questions per stage):

| brain file | size | letters | numbers | math | words | world | talk | overall |
|------------|-----:|--------:|--------:|-----:|------:|------:|-----:|--------:|
| float32 | 2.6 MB | 100 | 97.3 | 99.7 | 99.0 | 96.7 | 92.7 | 97.6% |
| int8, rounded | 679 KB | 100 | 97.3 | 99.7 | 99.0 | 96.7 | 92.7 | 97.6% |
| int4, rounded | 364 KB | 100 | 97.3 | 99.7 | 99.0 | 96.0 | 91.7 | 97.3% |
| int3, rounded | 280 KB | 86.7 | 89.3 | 97.0 | 85.0 | 88.3 | 51.7 | 83.0% |
| ternary, rounded | 156 KB | 15.7 | 7.7 | 7.7 | 3.0 | 0.7 | 0.0 | 5.8% |
| **ternary, squeezed** (shipped) | **153 KB** | **100** | **97.3** | **99.7** | **99.0** | **97.3** | **93.3** | **97.8%** |

Rounding a trained brain is free down to 4 bits and destroys it below that. **Squeezing** it
instead (continuing to learn *through* the rounding, below) gives a 1.58-bit brain that is
**17x smaller than float32 and as good as the original**. The ternary levels come out almost
exactly evenly split (32.5% / 34.6% / 32.9%), so packing 5 weights per byte is within 1% of the
entropy limit. To go smaller you need fewer parameters or fewer bits, not better coding.

**Speed:** the numpy runtime generates about 1,400 characters per second on **one** CPU thread.
One numpy training step (8 x 128 characters) takes about 0.23 s on 2 threads.

## Compression to the extreme: `squeeze`

```sh
python -m morpheus squeeze --ckpt out-morpheus/morpheus.pt --scheme ternary
```

[`morpheus/quant.py`](morpheus/quant.py) is the single source of the quantization math, in numpy (for storage) and
PyTorch (for training). Tests check that the two and the stored file agree **bit for bit** for
every scheme:

| scheme  | levels         | scale (fp16)                     | stored as                      |
|---------|----------------|----------------------------------|--------------------------------|
| int8    | -127..127      | max per row                      | 1 byte per weight              |
| int4    | -7..7          | max per 32 weights               | 2 weights per byte             |
| int3    | -3..3          | max per 32 weights               | bytes, LZMA-squeezed           |
| ternary | -1, 0, +1      | least-squares fit per row        | 5 weights per byte (3^5 = 243) |
| binary  | -1, +1         | mean per row                     | 8 weights per byte             |

Ternary is the "1.58-bit" format of BitNet b1.58: every weight is one of three values, so a
matrix-vector product is only additions and subtractions. `squeeze` is quantization-aware
training with distillation:

1. A copy of the brain (the *student*) sees only its rounded weights in every forward pass.
   Updates go to float weights underneath (the straight-through estimator).
2. It studies the whole curriculum, learning from the lessons *and* from the original
   full-precision brain (the *teacher*).
3. It sits its exams in compressed form. When two exams in a row are back within 1 point of the
   teacher, it **dreams**: the learning rate fades to zero. In our run the constant-rate phase
   bounced between 89% and 94.5%. Dreaming lifted it to 97.8%.

In our run, squeezing to ternary took 4,000 steps and about 10 minutes.

**The ternary scale must be idempotent.** BitNet's scale is `mean|w|`. After a round trip
through a file, a third of each row is exactly zero, so the mean shrinks and re-rounding would
shrink every weight by a third. We caught this when a reloaded ternary brain scored 57% instead
of 97.8%. Morpheus picks the levels BitNet's way, then fits the scale by least squares. That is
more accurate, and re-rounding changes nothing. A test guards this for every scheme.

## Morpheus as your assistant

[`morpheus/assistant.py`](morpheus/assistant.py). A 0.7M-parameter brain is great at what it was
taught and hopeless at everything else, so practical jobs go to **skills**: small, exact tools
that need no model inference at all. Whatever no skill claims goes to the brain.

| skill       | say                                                            |
|-------------|----------------------------------------------------------------|
| notes       | "remember that my locker code is 4071" / "what is my locker code?" / "forget my locker code" |
| to-do       | "add milk to my list" / "what's on my list?" / "remove milk from my list" / "done milk" |
| reminders   | "remind me to call mom at 5pm" / "remind me in 20 minutes to stretch" |
| alarms, timers | "set an alarm for 6:45 am" / "set a timer for 10 minutes" (the phone's Clock app on Android) |
| checked answers | any arithmetic, "which is bigger, 73 or 37?", story problems |
| clock, battery | "what time is it?" / "what is the date?" / "how much battery?" |
| look up     | "tell me about volcanoes" (Simple English Wikipedia, only if allowed) |
| search      | "search the web for pizza near me" (opens the browser)          |
| voice       | `chat --voice` listens and speaks (Android, Termux:API)          |

**Checked answers** are how the assistant stays reliable while the brain keeps learning.
Morpheus answers first and a tool checks the answer. If the brain was wrong (in testing it
once said "the bigger of 73 and 37 is 77"), you get the correct answer, and the correction is
saved as a lesson for the next learning session. The brain learns from its own mistakes.

## Lifelong learning, on any device

[`morpheus/learn.py`](morpheus/learn.py) and [`morpheus/grad.py`](morpheus/grad.py). Backpropagation for Morpheus is written by
hand in numpy (tests check every gradient and the AdamW step against PyTorch), so Morpheus
can keep learning where PyTorch doesn't run, like a phone.

```sh
python -m morpheus learn        # one session (only while charging; --force to override)
python -m morpheus teach "what is my dog called?" "rex is your dog."
python -m morpheus settings allow_internet on    # off by default
python -m morpheus status
python -m morpheus undo         # back to the brain before the last session
```

Everything lives in `~/.morpheus` (or `$MORPHEUS_HOME`): settings, the brain, notes, lists,
reminders, taught facts, and a library of everything read, LZMA-compressed. A session:

1. **Checks power.** It only learns while charging, so it runs on the grid, not your battery.
2. **Reads** new `.txt`/`.md`/`.html` files from `~/.morpheus/inbox` and `Download/morpheus`.
   Only if the internet is allowed, it also reads a few random Simple English Wikipedia articles.
3. **Studies.** Every batch mixes two kinds of rows:
   - **Review rows** cover the whole ABC curriculum. Here Morpheus also matches its own
     pre-session answers ("learning without forgetting").
   - **New rows** hold new reading and taught facts, learned freely. They get rows in proportion
     to how much new material there is. Early testing showed one short file given too much
     weight leaked into unrelated answers ("apples around the earth").

   Taught facts come with **near-misses**: while learning "capital of france → paris", it also
   sees "capital of zobek → i have not learned that yet". Without them, one taught fact answered
   every similar question ("capital of spain → paris").

   The session ends in a short dream, as the learning rate fades to zero.
4. **Sits the exam** before and after. The new brain is kept only if it lost at most 2 points
   compared with both the last brain and the original one, so small losses can't pile up.
   Otherwise the session is rolled back.

A compressed brain keeps learning **in its own format**. The numpy trainer thinks with the
rounded weights and updates float weights underneath, so a ternary brain stays ternary.
Low-bit brains use a larger learning rate (1e-3), so weights can cross rounding thresholds.

In testing, one 200-step session on the 153 KB ternary brain gave these results:

| question                         | before                           | after                           |
|----------------------------------|----------------------------------|---------------------------------|
| what is the capital of france? (taught) | i have not learned that yet.     | paris is the capital of france. |
| what is the capital of spain?    | i have not learned that yet.     | i have not learned that yet.    |
| what color are apples?           | apples are red.                  | apples are red.                 |
| curriculum exam                  | 98.3%                            | 98.1%                           |

## Teaching Morpheus something new

Adding knowledge is writing a fact function and putting it in a stage:

```python
# in morpheus/curriculum.py
PLANETS = "mercury venus earth mars jupiter saturn uranus neptune".split()

def planet_order(rng):
    i = rng.randrange(len(PLANETS) - 1)
    return f"after {PLANETS[i]} comes ", PLANETS[i + 1], ""   # prompt, answer, rest

STAGES.append(Stage("space", "the planets", [
    # (lesson weight, exam weight, fact)
    (1, 1, planet_order),
]))
```

Then `python -m morpheus train --resume` continues from the next stage it has not taken.
To let Morpheus *talk* about the new facts, also add a `qa(...)` question for them to the
`talk` stage. Before training, run the tests: `test_exam_prompts_have_one_answer`
catches facts that contradict each other, for example a prompt with two possible answers.

## Honest limits, and how to grow

- Morpheus knows what its curriculum teaches, what you teach it, and what it reads. Anything
  else gets "i have not learned that yet". A tiny model that knows its limits beats one
  that invents answers.
- Reading teaches it words and style far more than facts. A 0.7M-parameter model can't
  memorize an encyclopedia. For facts that must be right, use `teach`, which it studies until
  it answers them.
- It is a character-level model with a 128-character memory, enough for a few turns of
  conversation.
- The brain's own math covers what it was taught (sums up to 20 + 20, times tables to 10).
  The assistant's calculator covers the rest.
- Ways to grow: add stages (above); read books (`--library`, or the phone inbox); raise a
  larger mind with `--size micro`, a longer `--block_size`, or a GPU; and later, teach the
  brain to call its skills itself instead of routing by pattern.
